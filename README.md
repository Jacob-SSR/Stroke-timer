# Stroke Fast Track · Next.js + TypeScript

โปรเจกต์ใหม่จาก `stroke-timer.zip` ใช้ Next.js App Router, React และ TypeScript เป็นหลัก หน้าจอธีมเขียวมิ้น ตัวอักษรอ่านง่าย ใช้ได้บนคอมพิวเตอร์ แท็บเล็ต และโทรศัพท์ ข้อมูลในโหมดตัวอย่างเป็นผู้ป่วยสมมติทั้งหมด

## เริ่มใช้งาน

ต้องมี Node.js 22.13 ขึ้นไป แนะนำรุ่น LTS ที่รองรับ `node:sqlite`

```powershell
npm ci
Copy-Item .env.example .env.local
npm run dev
```

เปิด `http://127.0.0.1:3001` พอร์ตเริ่มต้นแยกจากโปรเจกต์ STEMI ที่ใช้ 3000 ยังไม่ต้องตั้ง HOSxP หรือ Google Sheet เพื่อดูตัวอย่าง

Production:

```powershell
npm run build
npm start
```

คำสั่งเริ่มแอปผูกเฉพาะ loopback ให้ใช้ reverse proxy ภายในโรงพยาบาลที่ตั้ง TLS และจำกัดเครือข่ายตามระบบเดิม ตัวอย่างอยู่ใน `deploy/nginx.conf.example` เก็บ Host header ให้ตรงเพื่อให้ตรวจ Origin ได้

## ความสามารถ

- ลำดับเวลา Stroke 8 ขั้นตอนและเป้าตาม ZIP: แพทย์ 10, DTX 10, EKG 20, ส่ง Lab 20, ประสาน 15, ปลายทางรับ 20, รถพร้อม 25, รถออก 30 นาที แก้เป้าในหน้าตั้งค่าได้
- Onset / Last known well, ไม่ทราบเวลา, Onset→Door และกรอบเวลา 4.5 ชั่วโมงตามต้นฉบับ แสดงข้อมูลประกอบการส่งต่อ การตัดสินใจรักษาเป็นของแพทย์และโรงพยาบาลปลายทางหลัง CT
- NIHSS 15 ข้อ พร้อม UN, คะแนนที่ยังไม่ครบแสดงว่าเป็นคะแนนบางส่วน ไม่ใช้แทนคะแนนรวม กรอกคะแนนรวมเองได้ การแก้คะแนนรวมจะล้างรายข้อเพื่อไม่ให้ข้อมูลขัดกัน
- GCS E/V/M รองรับ T และ A และไม่สร้างคะแนนรวมตัวเลขเมื่อประเมินไม่ครบ บันทึก NIHSS/GCS ลงหมายเหตุพร้อมเวลาของเซิร์ฟเวอร์ได้ ใช้เงื่อนไขแจ้งสำคัญจากต้นฉบับเมื่อ NIHSS เพิ่ม ≥4, GCS ลด ≥2 หรือ GCS ≤8
- BE-FAST, DTX, BP, เลือกผู้ป่วย ER ตามวันและแสดงเวลามาถึง, เริ่มก่อนลงทะเบียนและผูก VN ภายหลัง
- อ่านรหัส I60–I64, G45, G46 เพื่อเพิ่มเคสอัตโนมัติ อาการเข้าข่ายแสดงป้ายให้เจ้าหน้าที่เลือกเอง ไม่วินิจฉัยจากอาการสำคัญ
- ปุ่ม ✕ นำรายการที่เลือกผิดออกพร้อมยืนยัน ไม่สร้างเคสปิด/KPI/คิว Sheet และเลือกผู้ป่วยเดิมเริ่มใหม่ได้
- หมายเหตุสำคัญ แถบแจ้งเตือน และปุ่มเปิดเสียงสำหรับบันทึกสำคัญใหม่
- ผลหลัง Refer / D/C: CT, เวลาถึงปลายทาง, rtPA/Needle/เหตุที่ไม่ได้, Thrombectomy, Dx, วันและสถานะจำหน่าย, mRS, Barthel, IMC
- คำนวณ Onset→Needle, Door ต้นทาง→Needle, Door ปลายทาง→Needle และเวลาเดินทาง เมื่อข้อมูลครบและเรียงเวลาถูกต้อง กรณีไม่ทราบ Onset หรือไม่ได้ rtPA จะเว้นตัวชี้วัดที่เกี่ยวข้อง
- ทะเบียนเคส, Dashboard/KPI รายเดือน, ผลการรักษา, RCA / 5 Whys / มาตรการ, ส่งออก Word/Excel/CSV/PowerPoint และ PDF ผ่านหน้าพิมพ์ของเบราว์เซอร์
- เครื่องมืออ่าน EKG เดิมอยู่ใน iframe บน origin เดียวกัน พร้อมตรวจ origin/source/case ID ผล AI ยังต้องให้แพทย์ยืนยัน
- คัดลอกสรุป/เลือกผู้รับใน LINE หรือส่งผ่าน LINE OA หลังผู้ใช้กดยืนยันและตั้งค่าฝั่งเซิร์ฟเวอร์ ไม่มีการส่งอัตโนมัติเมื่อเปิดหรือปิดเคส

## HOSxP อ่านอย่างเดียว

แก้ค่าใน `.env.local` ฝั่งเซิร์ฟเวอร์ แล้วเริ่มใหม่ ใช้ `STROKE_DEMO=false` พร้อม `STROKE_ACCESS_TOKEN` ที่ตั้งเองและบัญชี MySQL ที่มีสิทธิ์ SELECT เท่านั้น ค่าใน `.env.example` เป็นชื่อการตั้งค่าและช่องว่าง ไม่มีรหัสจริง

หา lab_items_code จริงของโรงพยาบาลแล้วกรอก `HOSXP_LAB_ITEMS` เป็นชื่อกลุ่มและรายการรหัส เช่น CBC, PT/INR, BUN, Cr, Glucose ไม่ใส่รหัสสมมติให้ระบบจริง

| ข้อมูล | แหล่งเวลา |
|---|---|
| Door-in | `ovst.vstdate` / `vsttime` |
| ส่ง Lab และผล Lab | `lab_head` / `lab_order` เฉพาะรหัสที่ตั้งไว้ |
| Door-out | เวลาบันทึก `referout` ใช้อ้างอิง ควรกดแก้เป็นเวลารถออกจริง |
| แพทย์, DTX, EKG, ประสาน, ปลายทางรับ, รถพร้อม | กดบนจอเท่านั้น |

ไม่มีการอ่านเวลาสั่งยาเป็นเวลา DTX/EKG หรือ Needle ไม่ต้องตั้ง EKG/lytic codes สำหรับโปรเจกต์นี้ เวลา Needle ในผลหลังส่งต่อกรอกจากข้อมูลปลายทาง

SQL อยู่ใน `src/lib/hosxp.ts` ใช้ parameterized SELECT เท่านั้น ตารางที่ต้องอ่านคือ `ovst`, `er_regist`, `patient`, `opdscreen`, `ovstdiag`, `referout`, `lab_head`, `lab_order`, `pttype`, `thaiaddress` ตรวจ schema/charset/เวลาเครื่องกับ HOSxP ของโรงพยาบาลจริงก่อนใช้งานผ่าน `/api/stroke?action=diag` หลังล็อกอิน

รหัสเข้าใช้งานเป็นรหัสร่วม เก็บใน HttpOnly cookie แยกจาก STEMI ยังไม่มีบัญชีรายบุคคลหรือ audit log ระบุตัวผู้แก้ไข

## Google Sheet (ไม่บังคับ)

ใช้เพียง `GOOGLE_SERVICE_ACCOUNT_EMAIL`, `GOOGLE_PRIVATE_KEY`, `GOOGLE_SHEET_ID` เปิด Sheets API และแชร์ชีตให้ Service Account เป็นผู้แก้ไข รองรับ private key ที่มี newline จริงหรือ `\n` ห้ามใส่ private key ใน Git หรือแชต

โปรแกรมสร้างแท็บ `STROKE_FastTrack` และหัวตาราง 35 คอลัมน์เมื่อแท็บว่าง หยุดส่งหากหัวตารางไม่ตรง ห้ามเปลี่ยนชื่อคอลัมน์เอง ส่งซ้ำ upsert ตาม case_id เพื่ออัปเดตแถวเดิม เก็บคิวถาวรใน SQLite และลองใหม่ทุกนาทีขณะที่มีจอ polling มี lease ประสาน worker ในเซิร์ฟเวอร์เดียวกัน ใช้หนึ่ง deployment เขียนแต่ละชีต

ค่าเริ่มต้นเว้นชื่อ หมายเหตุและข้อความอิสระบางส่วน แต่ยังส่ง HN/VN และข้อมูลตัวชี้วัด ใช้ `GSHEET_SEND_PII=true` เฉพาะเมื่อต้องการเปิดส่งส่วนที่ซ่อนและกำหนดสิทธิ์เข้าถึงชีตแล้ว โปรเจกต์นี้ยังไม่ได้สร้างหรือแชร์ Google Sheet ใหม่จริง

## LINE และ AI ภายใน

ส่งผ่าน LINE OA: ตั้ง `LINE_CHANNEL_ACCESS_TOKEN` และ `LINE_TARGET_ID` บนเซิร์ฟเวอร์ จากนั้นเปิดสรุปเคสและกดส่งกลุ่มที่ตั้งไว้ ระบบขอยืนยันก่อนส่งและปกปิดชื่อ/HN ในข้อความ คัดลอกหรือเปิด LINE เพื่อเลือกผู้รับใช้ได้โดยไม่ตั้งค่า OA

หน้า EKG และตัวช่วยร่าง RCA เรียก AI เฉพาะเมื่อผู้ใช้สั่ง ตั้ง URL/โมเดลภายในที่โรงพยาบาลอนุญาตและตรวจ CORS/TLS ให้ตรง เครื่องลูกต้องเข้าถึงบริการ AI ได้ ไม่รวมโมเดลหรือ credential มาในโปรเจกต์

## ข้อมูลและสำรอง

SQLite อยู่ใน `STROKE_DATA_DIR` (ค่าเริ่มต้น `./data`) แยกจาก STEMI ทุกจอที่ใช้เซิร์ฟเวอร์นี้เห็นชุดเดียวกัน เก็บนอก public ไม่ได้ import `state.json` ของ PHP อัตโนมัติ ZIP ต้นทางที่ได้รับไม่มีข้อมูลผู้ป่วยจริง

```powershell
npm run backup -- ./backups/stroke-backup.sqlite
```

สำรอง online ด้วย SQLite snapshot ไม่เขียนทับไฟล์เดิม เมื่อต้องกู้คืนให้หยุดแอปและสำรองชุดปัจจุบันก่อนแทนฐานข้อมูล
